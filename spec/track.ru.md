# Трек: сетевые профили

Статус: **ЧЕРНОВИК**, 2026-09-27 (имена команд обновлены по принятой форме командной строки). Спецификация: `spec/network-profiles.md` (черновик, N1–N14, учтены два независимых ревью). Роадмап: веха M7, после архивации agents-infra (решение оператора 2026-09-23: сеть идёт после launch profiles).

## Зачем

Нескольким агентам на одной машине нужно выходить в сеть через разные выходы уровня приложения (VPN A, VPN B, корпоративный прокси). При этом нельзя менять ни оркестратор, ни соседних агентов, ни операционную систему.

## Что строим

- Библиотеку `curator-network-profiles` (собственный публичный репозиторий; ей пользуются task-board и публичный `curator-run`): `resolve → validate → probe → patch`.
- `--network <name>` у `curator run` и `task-board spawn` (`task-board claude|codex` — псевдонимы `curator run`); значения по умолчанию из слоя оператора (выбор агентов) и привязок сред выполнения; сетевые профили машины в `~/.curator/network.toml`, которыми управляет провайдер Curator `curator-network` (`curator network list|show|add|remove|check [--probe]|confirm|exec`).
- Патч применяет хост, который создаёт процесс (`unset`, затем `set`), и никогда через общее окружение; привязки сравниваются по дайджесту; возобновление при изменившемся профиле отклоняется.

## Интеграция

Как каждый владелец процесса применяет патч, где записывается привязка и как отклоняется возобновление при изменившемся профиле: `docs/integration-contract.md` (предложение, отправленное за советом по правилу 27 2026-09-30; решает Иван). Нормативные правила дайджеста, `EnvPatch` и равенства — в `spec/contract-appendix.md`, поставленном с N-A.

## Зависимости

N-C1 нужны M2 и M3 (task-board и tb-sessiond собирают запуски через модуль); N-C2 нужна M4 (слой оператора и привязки). Мост инструментов Apiary должен держать собственный транспорт вне профиля агентской среды (NP-N11).
